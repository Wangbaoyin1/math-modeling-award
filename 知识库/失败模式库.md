# 失败模式库（错题本）

> 用途：把每次踩的坑沉淀成规则，赛前/赛中自动规避。**这是你插件里越攒越值钱的护城河。**
> 每条格式：现象 → 根因 → 规避方案。

## #1 Windows 控制台 GBK 编码报错

- **现象**：Python 脚本 `print("✅ ...")` 或输出中文时抛 `UnicodeEncodeError: 'gbk' codec can't encode ...`。
- **根因**：Windows 控制台默认 GBK 编码，不认 emoji/部分 Unicode 字符；PowerShell 还会把 stderr 警告误判成 NativeCommandError（exit code 1）。
- **规避方案**：每个求解脚本开头加一行——
  ```python
  import sys
  sys.stdout.reconfigure(encoding="utf-8")
  ```
  或避免在 print 里用 emoji；matplotlib 中文用 SimSun + `axes.unicode_minus=False`。

## #2 UltraMath 论文门禁漏洞（只有公式，无图无解释）

- **现象**：用 UltraMath 跑赛题，产出的论文只有公式和结果，没有图表、没有文字解释。
- **根因**：UltraMath 论文阶段硬门禁只查「编译通过 / 代码可跑 / 摘要无数值 / 无目录页」，**缺少"内容完备性"门禁**——没要求"每问必须有图 + 文字解释 + 结果表 + 敏感性 + 模型检验"；且 `check_figures.py` 只扫 `求解/` 里的 PNG 质量，**从不检查论文正文是否真的引用了图**。
- **规避方案**（将写入自定义插件的硬门禁）：论文.tex 必须满足：① 每问 ≥1 处 `\includegraphics`；② 三线表数量 ≥ 问题数；③ 含敏感性/模型检验节；④ 每图有 ≥3 句分析。

## #3 灰色预测 GM(1,1) 的适用边界

- **现象**：有人拿灰色预测硬套大数据、强周期序列，预测离谱。
- **根因**：GM(1,1) 只适合**少数据（≥4 点）+ 指数趋势**；大数据/强周期应换 ARIMA 或季节性模型。
- **规避方案**：数据量 >20 或含周期 → 优先 ARIMA/SARIMA；仅"少数据 + 单调趋势"才用灰色预测。

## #4 高维盲搜找不到"零测度"遮蔽区域

- **现象**：优化航向/速度/起爆点时，差分进化在宽范围随机搜索，遮蔽区域极窄（T 恒为 0）。
- **根因**："遮蔽"要求起爆点精确落在导弹轨迹与视线交点上，参数空间里几乎测度为零。
- **规避方案**：**轨迹参数化**——把起爆点参数化为"导弹轨迹上的点 + 时间偏移"，让命中条件自动满足，只优化可达性约束。

## #5 可达性约束不完整导致物理矛盾解

- **现象**：反推无人机参数时，起爆时刻 te 与"投放+抛体"时间对不上（te 早于抛体时间 dt）。
- **根因**：漏了 `te ≥ dt` 约束。
- **规避方案**：约束清单逐项列全——①起爆点 z ≤ 投放高度 ②te ≥ dt ③速度 v=水平位移/te ∈ 区间。

## #6 差分进化在强约束下陷局部最优

- **现象**：高维 + 强耦合约束时，差分进化给出"某一架无人机起爆过晚"的局部解。
- **根因**：强约束地形把可行域切成孤岛，进化算法难以跨越。
- **规避方案**：参数化缩小空间（见 #4）+ 多起点局部优化 + 必要时网格粗扫定位可行域再细化。

## #7 评测发现：优化深度不足（2025A 复盘）

- **现象**：我的 Q2=3.12s vs 公开 4.54-4.81s；Q4/Q5 差距更大。
- **根因**：① 航向被物理锁死 180°（最优 176.62°，物理约束用于缩小范围但不能替代优化）；② 单差分进化弱于"网格+随机+坐标下降"混合；③ Q5 只做基线没做完整分配。
- **规避方案**：优化要"多策略混合 + 足够预算"，任务先明确完整目标再逐问加码。

## #8 matplotlib 找不到 SimHei（中文/负号问题）

- **现象**：图表中文变方块、报 `Font 'default' does not have a glyph for −` 警告。
- **根因**：matplotlib 未自动扫描 Windows 字体，SimHei 需手动注册；负号警告是字体回退噪音，图实际渲染正常。
- **规避方案**：
  ```python
  import matplotlib.font_manager as fm
  fm.fontManager.addfont(r"C:\Windows\Fonts\simhei.ttf")  # 先注册
  plt.rcParams["font.sans-serif"] = ["SimHei", "Microsoft YaHei", "Arial"]
  plt.rcParams["axes.unicode_minus"] = False
  ```
  （已固化在 `知识库/模型工具箱/图表库.py`，直接 import 即可。）

## #9 窄窗口参数的敏感性扰动要小

- **现象**：2025A 烟幕对起爆间隔 dt 做 ±30% 扰动，遮蔽时长全变 0（−100%），龙卷风图全"废"。
- **根因**：遮蔽窗口极窄（dt 只在 3.5~4.5s 有遮蔽），±30% 扰动把参数推出可行域。
- **规避方案**：敏感性扰动幅度**匹配问题特性**——窄窗口/阈值型参数用 ±5% 小扰动或绝对量（±0.5s），宽范围参数才用 ±20~30%；先画"结果 vs 参数"曲线看清窗口再定扰动。

## #10 污染源反演别把"峰值点/低 R² 拟合"当结果

- **现象**：2011A 用单源各向同性高斯对实测场拟合，R² 仅 0.003~0.046，却据无效 σ 报结论；或直接把浓度最高采样点当污染源。
- **根因**：① 真实污染场是多源叠加 + 受风向/地形调制的弥散场，单源高斯假设必然失效；② 峰值点受扩散偏移，≠ 源点。
- **规避方案**：先做**诚实分级**（有气象/源谱→严格反演；只有浓度场→描述性定位）。无气象数据时：源定位以「梯度场指向 + 峰值点聚类 + 功能区交叉」三重证据为主，σ 只报量级（"羽流尺度"）；高斯拟合 R² 低要**如实披露并降级**，不硬凑。完整方法见 `知识库/模型工具箱/算法知识卡_07_污染源反演.md`。

## #11 过程型决策题：解析期望公式的"递归/丢弃"口径陷阱（仿真优先！）

- **现象**：2024B 生产决策（检测→换新→拆解→重装→再卖），我第一版解析期望公式把"丢弃坏品"写成成本 −P，导致**假收益**（丢了反而"赚"P），6 案例全错选且收益虚高到 40+；第二版事件树又陷递归混乱。
- **根因**：带无限递归（检出坏→换新→可能再坏→再换…）与多条售后路径（检出丢弃/漏卖被退/拆解重修）的决策题，**解析闭合公式极易在口径上出错**——"丢弃收益应=0 而非 −P""拆解重检是否无条件（假设c：是）""合格零件拆解时是否也收重检费""被退是否强制拆一次"。任一搞错，收益整体偏移→决策翻转。
- **规避方案**：
  1. **仿真优先**：过程/递归型决策题直接用**蒙特卡洛枚举**（状态机模拟 + 2万+采样 + 固定 seed），解析只做近似互证（呼应模板16但升级为"仿真优先"）；
  2. **编码前钉死口径**：把题目的每一条路径规则写成显式清单再写代码（丢弃=0 收入、拆解必重检全部件、被退无条件拆一次…）；
  3. **死循环防护**：拆→重装→再坏→再拆必须加 guard（如 200 次上限），并保证每轮"修到合格"概率>0；
  4. **参考实现勿盲从**：国二自己的代码也有口径细节问题，用大采样（10万+）+ 解析反证确认最优，而非"复现参考代码即正确"。
  - 完整记录：`评测集/2024B_题型补盲实测记录.md`。

## #12 MiKTeX 引擎在受限沙箱里"无法产出 PDF"（日志/子进程被拒）

- **现象**：`xelatex`/`pdflatex` 开头就报 `log4cxx: setFile(...\miktex\log\xxxx.log) 拒绝访问`，随后 `Sorry, but ... did not succeed`，**不生成 PDF**（有时先排版到第 1 页再失败）。
- **根因（叠加的三条限制，均非代码问题）**：
  1. **进程对 `C:\Users\<user>` 无写权限**（含 `AppData\Local\MiKTeX\miktex\log`），MiKTeX 把日志写那儿 → log4cxx 失败 → TeX 引擎判"致命"；
  2. **沙箱禁止 `CreatePipe` 拉子进程**，MiKTeX 的"自动重建 `xelatex.fmt`/`fndb refresh`/写 PDF 时的 `miktex-dvipdfmx.exe`"全被拒 → `Windows API error 5`；
  3. （次要）注册表 `Software\MiKTeX.org` 写被拒。
  此外还会遇到：`C:\Users\<user>` 整目录不可写但**工作区/临时目录可写**；`.ps1` 用 UTF-8 无 BOM 时 Windows PowerShell 5.1 把中文读成乱码；旧目录被先前（提权）会话锁了 ACL。
- **规避方案（本环境已验证跑通，产出正式 PDF：19 页 / 0 Error / 745KB）**：
  1. **重定向 MiKTeX 用户数据/配置到可写目录**：`$env:MIKTEX_USERDATA/USERCONFIG/COMMONDATA/COMMONCONFIG` 指向 `%TEMP%\mikrt`（ASCII、可写）等；「可写目录」指当前令牌能写的位置（探测法：往候选目录写一个 `_w.txt`）。
  2. **预复制格式**：把 `C:\Users\<u>\AppData\Local\MiKTeX\miktex\data\le\xetex\xelatex.fmt` 复制到重定向 `userdata\miktex\data\le\xetex\xelatex.fmt` 的规范路径 → MiKTeX 直接加载格式、**跳过自动重建**（避开 CreatePipe/`Formats build`）。
  3. **用 `xelatex -no-pdf` 两遍**（生成 `.xdv`，不触发 dvipdfmx 子进程），再**手动** `miktex-dvipdfmx xxx.xdv -o xxx.pdf`（dvipdfmx 本身不依赖被禁的子进程）。
  4. **不要用 `powershell -File` 包子脚本**：子 PowerShell 令牌更受限（连工作区子目录都写不进）；应**在宿主 shell 内直接 `Start-Process xelatex.exe`**（继承宿主写权限）。
  5. **一次交互命令 >300s 会被截断** → 用"后台分离进程 + 状态文件轮询"：脚本 `-Step start`（准备+启动第1遍，立即返回）/ `-Step poll`（自动推进：pass1→pass2→dvipdfmx，并向 `compile_status.txt` 追加 `START / PASS1_DONE / PASS2_DONE / DONE exit=0 Error=0 size=...`）。
  6. **`.ps1` 纯 ASCII 化**：中文路径一律通过命令行参数（Unicode 安全）传入，避免 PS5.1 按 ANSI 读 `.ps1` 的中文乱码。
  7. 若某些目录被旧会话锁 ACL：改用**每次新建的临时目录**作 MiKTeX userdata。
  - 可复用思路：按上述四步（重定向 MiKTeX 用户目录 → 预复制格式 → ASCII 文件名编译 → 回改中文名）写成脚本；关键是把 `MIKTEX_USERDATA/CONFIG/COMMONDATA/COMMONCONFIG` 指到可写临时目录。
- **判断标准**：正常环境（用户主目录可写、允许子进程）直接 `xelatex 论文.tex` 即可；只有"用户主目录不可写 + 禁子进程"的受限沙箱才需要这套绕过。

### #12 补充（2026-09 二次实测，定位到「注册表 + 命名管道」）

- **更精确的卡点**：`xelatex -no-pdf` 能成功出 `.xdv`（xetex 引擎不写注册表），但 `xelatex`（带 PDF）和 `xdvipdfmx` 启动时**写注册表 `HKCU\Software\MiKTeX.org` + 走 CreatePipe 命名管道**，这两项被沙箱拒绝 → dvipdfmx 启动 0.2 秒致命错误（"未检查更新"状态也是写注册表的一部分）。
- **关键区分（决定成败）**：**临时 pwsh 工具 + `sandbox_permissions=danger-full-access` 能覆盖注册表/命名管道**（实测 `xelatex` 带 PDF 成功 0 Error 5 页）；而 **persistent 持久 shell 的沙箱连提权都不覆盖这两项**（编译进程写 AppData/ProgramData/HKCU 全被拒）。**结论：编译 LaTeX 必须用临时 pwsh + danger-full-access，不能依赖持久 shell。**
- **工具层面的根因（2026-09 三查）**：`sandbox_permissions` 提权参数**只在 `@deepseek-ai/dsh-tool-pwsh`（工具名 `pwsh`）上**；而 persona 原本只有 `terminal-pwsh`（`@deepseek-ai/dsh-terminal-bash`）和 `persistent-pwsh`（`@deepseek-ai/dsh-tool-pwsh-persistent`），**这两个工具都不带 `sandbox_permissions`**，所以插件会话里 agent 无论怎么写都提不了权，只能试 UAC（`-Verb RunAs`，被沙箱拦截"operation was canceled by the user"）。**解决：persona 补 `- id: tool-pwsh / name: '@deepseek-ai/dsh-tool-pwsh'`（loose 行，不发布 service），编译 LaTeX 时用它 + `sandbox_permissions=danger-full-access`。**
- **已排除的绕过路径**：① lualatex —— `cumcmthesis.cls` 第 34 行 `\RequireXeTeX` 强制 XeTeX，lualatex 被模板拒绝；② dvisvgm —— 它是 DVI→SVG 工具，`--pdf` 是反向（PDF→SVG）且依赖 Ghostscript（本机无 gs），不能作 .xdv→PDF 转换；③ 手动"更新 MiKTeX"——不改变进程每次启动写注册表状态的行为。

## #13 机理题"物理约束事后校验"而非"建模约束"（2021A FAST 教训）

- **现象**：几何/机理结果正确（2021A 顶点差 <0.1m、焦距 Lf=280.854 与自研 p=140.326 本质一致），但物理量超标（应变 0.111% vs 题设 ≤0.07% 合规）→ 判定 SUSPECT。
- **根因**：把题设的物理硬约束（应变/促动器行程/安全边界/量程）当作**事后校验**（算完再回头查是否超），而不是**建模阶段的硬约束**（优化时就把 ±0.07% 应变作为不等式约束纳入）。
- **后果**：几何对了但"物理不可行"——评委一眼看出结果违背题设硬约束，直接降档。
- **规避（铁律）**：**题设里的物理硬约束（应变/行程/间隙/安全边界）必须在建模阶段就作为不等式约束纳入优化**。例：2021A 把 `(1-0.07%)² ≤ d²/d₀² ≤ (1+0.07%)²` 作为约束(6-8)，与促动器 ±0.6m 一起进整体优化（BFGS），而不是逐点径向投影后回头查应变；对应改进=用"节点坐标+伸缩量双决策变量整体优化"替代"节点严格沿径向"。
- **判断标准**：凡题设给出"不超过 X%"或"±X m"的物理量，先自问"这是约束还是校验？"——是约束就进建模目标/约束；只打算事后看，就是本坑。A 类机理题（FAST/炉温/作业服/波浪能/烟幕）反复出现。

## #14 审稿只做"内审自审"、跳过三席独立盲评（Phase 4 被简化）

- **现象**：做完题只报"自审：无阻断项 B1-B9"，却没有产出三席（A/B/C）独立盲评 scorecard 与聚合档位——Phase 4 没真正走完，但用户/交付误以为"已终审"。
- **根因**：persona 把 Phase 4 写成一段（"逐项检查+阻断项 B1-B9；终审三席独立盲评"），agent 抓到前半段"自审无阻断项"即认为通过，没触发后面的三席盲评（派 3 个 subagent）。
- **后果**：缺"独立第三方盲评"的客观档位（国一/国二判定、明细评分），评审结论主观、不可复核；且缺 seat_A/B/C 证据链。
- **规避（铁律）**：Phase 4 必须拆三步且缺一不可：①面板自审（B1-B9 阻断项）②三席独立盲评（3 个并行 subagent，各注入不同 seat brief，只拿 PDF+产物清单，产出具名 scorecard）③聚合分档。**"自审无阻断项"仅代表内审通过，不等于终审完成；未产出三席 scorecard = Phase 4 未完成，须补做。**
- **判断标准**：交付审稿结论时，若只有"无阻断项/自审通过"而无 seat_A/B/C scorecard + 三席聚合档位，即踩本坑。

## #15 大型状态动态规划：资源二维 + 购买耦合 = 状态爆炸（务必先估规模）

- **现象**：2020B 穿越沙漠，用"逐箱 DP"状态=(天,节点,水,食物)求解。30天×27节点×400水×600食，加上起点/村庄购买枚举，状态爆炸。step=8 粒度时 day8 就 14 万状态、day30 仍上万；帕累托剪枝(保留非支配 (w≥,f≥,m≥))几乎压不掉——因为"多买资源→少资金"和"少买资源→多资金"并存，支配关系极少。
- **根因**：① 资源维度最大超出合理需求（别用"负重上限=400/600箱"做枚举上界，最优解资源只到"够用"量级）；② 村庄购买量又是一个自由枚举维度（capw×capf 可达几万/天/节点）；③ 每层对每(节点,资源)保留最大 m，资源网格精细时规模爆。
- **规避（铁律）**：写大型 DP 前**先估状态规模**（天数×节点数×单资源状态数×购买组合数），超过 ~10^6 就换模型。选项：① 把购买从状态剥离，只留"到达某节点时用 LP/A* 算最优购买"；② 用 MILP/整数规划让求解器处理购买维度；③ 资源按"足够用"而非"负重上限"做上界；④ 若 DP 必须，用"资源折算成资金当量"把二维资源压成一维。
- **判断标准**：开跑 3 分钟内状态数仍在增长未收敛，即踩本坑，回头重新设计，别硬等。

## #16 MILP 建模"到达终点即结束" 极易出逻辑 bug（资源平衡/隔空购买）

- **现象**：用 MILP 建模"穿越到终点即游戏结束"，初版正确性漏洞：① 玩家到终点后**资源仍被逐天消耗**（停留动作有基础消耗），导致资源错误递减、还需"续资源"；② **隔空购买**——`bw[t,v]` 变量允许在任意"村庄"购买，但没约束"玩家当天必须在该村庄"，于是 CBC 让玩家在矿山挖矿时"远程"在别处买水（buyW 在 pos=[12] 时 >0），资金虚高到 18280；③ **退款只算一次**被写成可多次套利。
- **根因**：① 到终点后是"游戏结束"，不应再有消耗/挖矿/购买——需用 `active[t] = 1 - x[t-1,end]` 把当天所有资源/资金变动乘 0（用 Big-M 线性化，且 eff 变量必须 ≥0，否则会因 `e >= expr - BIG*x` 取负值导致资金"反增长"）；② **购买必须受位置约束** `bw[t,v] ≤ BIG·x[t,v]`，且仅起点(第0天)/村庄可买，缺失此约束即产生"隔空购买"。
- **规避（铁律）**：① 到终点后所有变动量 active 门控，Big-M 中间变量一律 `lowBound=0`；② 每类动作的**发生位置必须与位置变量耦合**（购买≤BIG·x、挖矿≤x、移动用弧变量）；③ 解出来后**回代逐日数值验证**（每天资源单调、资金==初始-购买+挖矿-退款+退回、位置逐天相邻），任何一天不满足即模型有 bug，不能直接采信 CBC 的 objective。
- **判断标准**：解出来后资金在"到终点后"仍递增/递减、或资源在矿山却"买了水"、或退款被重复——即踩本坑。

## #17 验证手段优先级：确定性模拟器 > 求解器 objective（数值"看起来对"≠"合法"）

- **现象**：MILP/CBC 给的第一关 objective 从 9600(直接走)→18280(含虚拟隔空购买)→13640(修复后合法)。如果只看"求解器给出极大值"就采信，会虚高 30%+。真正的 13640 是靠**手写确定性模拟器逐天回代验证**后才确认合法的。
- **根因**：CBC 的 objective 只在**模型自身约束**下是正确的；若模型建模有 bug（缺位置耦合/到终点门控），objective 再"优"也是假解。竞赛题里"目标值大"不等于"答案对"。
- **规避（铁律）**：**悬空验证**——所有组合优化/最优路径结果，必须用一个独立的、逐天/逐状态的确定性模拟器回放，检查每一步的资源守恒、资金平衡、位置相邻、规则合规。模拟器验证通过才是可交付的合法解。**求解器结果只是候选，模拟器验证才是答案。**
- **判断标准**：交付前若只报 objective 数值、没有逐日回放表，即踩本坑。

## #18 先算清"值不值得做全流程"，再一头扎进求解器（止损意识）

- **现象**：2020B 从 Phase 0 框架一路建到 Phase 2 编码，最终在"第二关 MILP 13万变量"处卡住超时。**投入了大量轮次在第一关求解器的正确性打磨上**（DP→帕累托DP→MILP→修复MILP），但第二关、问题2/3、论文、验算、审稿全部没做。
- **根因**：前端为了"解出最精确的第一关数值"，反复在求解器 bug 里打转，没有预估"这道题完整交付需要哪些环节、每个环节的合理成本"，导致头重脚轻、整体烂尾。这是**项目级的时间分配失败**，不是单点技术失败。
- **规避（铁律）**：答题前先问"全部交付包含哪些环节（读题/框架/推导/编码/验算/论文/编译/审稿），每环节预算多少"；**先保证全流程能跑通交付，再回头精修数值**。求解器若 2 次以上为同一问题加班，立即切换更简单可靠的方案（如枚举+模拟器），而不是继续死磕。宁可第一关用"够好的 13640"，也不要为了"完美最优"把论文/后续问题耗没。
- **判断标准**：如果在单个问题的单个算法上占用超过整体时间预算的 1/3，且其他环节完全没动，即踩本坑，应立即止损转向整体交付。

## #19 盲目信任参考论文数值（把参考当标准答案，忽略√2/单位/拟合/读数错误）

- **现象**：拆解/参考优秀论文时，直接引用其数值当"标准答案"。2019A 高压油管拆解：某国奖示例问题一 `d100=0.29ms`，与正确值差 ~10 倍；其 P3 摘要 `483.33 rad/s` 实为正文表 `48.33` 的 ×10 笔误。若直接照抄其 0.29ms，整篇 P1 全错。
- **根因**：①参考论文（含国奖）也会犯**可拆的三类错误**——把 `E/ρ`(≈2554) 当 `P/ρ`(117.65)（差22×）；注2 的 `√(2ΔP/ρ)` 漏 √2（与自身另一处含√2矛盾，属复制笔误）；把图2 喷油峰 `20` 误读为 `2`（注入 4.4 vs 44mm³）。②作者把参考数值当"无误"，未做守恒自检。
- **规避（铁律）**：用《获奖方法论/优秀论文数值反向自检法.md》六步核验参考数值：①逐字对公式（√2/下标/ΔP·ρ vs ΔP/ρ/E/ρ vs P/ρ）；②守恒自洽（进=出、量纲）；③**比值量交叉验证**（ω、d150/d100、无量纲比率——这些对建模/单位/拟合误差不敏感）；④绝对量独立重算，看是否差**整数倍**（√2≈1.414、√1000≈31.6、×10、×22）；⑤复现性（有无代码/能否复现）；⑥结论/图/表/摘要一致性（三处对不上必有笔误）。
- **判断标准**：参考论文"比值量与你的模型吻合、但绝对量差一个整数倍" → 该文绝对量有口径/单位/拟合/读数错误，**只信其结构、重算其绝对量**，并在拆解笔记标注"数值口径可疑，绝对量不可引用"。
- **示例（2023B 多波束，2026-09 实测）**：优秀论文 Q4 摘要"测线总长 43466.62m"，但正文表3 分区求和=**434,662**——×10 笔误。用守恒自检（覆盖面积 68.5e6 ≈ 434662×157.6m）判表3正确、摘要掉数字。**结论：凡拆解参考论文，必用守恒/整数倍/比值量核验绝对量，别照抄。**

## #20 摘要/图注中文放进数学模式 `$...$` → 显示 □（字体缺失）

- **现象**：LaTeX 里写 `气泡面=$覆盖宽度 W$`（某段中文被包进 `$...$`），编译后该中文显示为方框 □；或摘要用 `① ② ③ ④`，ctex/FangSong 字体缺这些字形也显示 □。
- **根因**：`$...$` 内用数学字体（rm/italic），**无中文字形**，中文变 □；`①-④` 是 Unicode 带圈数字，部分中文字体缺字。
- **规避（铁律）**：① 中文一律放**数学模式外**（`气泡面为覆盖宽度 $W$`）；② 摘要序号用 `(1)(2)(3)(4)` 而非 `①-④`；③ 正文含中文的 `$\bm{…}$`、`\text{中文}` 也要避免，用 `$\bm{g}$（梯度方向）` 把中文放在 `$…$` 外。
- **判断标准**：PDF 里出现 □，先查"中文是否被包进 `$…$`"或"是否用了带圈数字/特殊符号"。

## #21 论文里的数值必须真算（审稿可抓出虚构值；"先写数后算"= 数据造假风险）

- **现象**：Q4 贪心敏感性，初稿写"把'中位相接'改为'第25分位相接'→242 海里/5.9%"，但**从未真跑该变体**；独立审稿 Seat C 实测 **290 海里/0.82%**，与 242/5.9% 不符。
- **根因**：为凑"论证"手写了数字，未从代码输出核对 → 触"数据真实性"红线（2026 官方：AI/数据造假取消评奖）。
- **规避（铁律）**：**所有写进论文的数值一律来自本机代码 `print`/保存文件，不手写**；凡要引用的对照/敏感性数字，先写脚本真算、再填入；改动后必须重跑代码核对。
- **判断标准**：论文里任何"若…则…"的数字，若无法由公开代码复现 = 疑似虚构，必须重算并修正。

## #22 真实地形"覆盖-长度权衡"交付点选偏（只取"最短总长端" → 漏测/过叠失分）

- **现象**：Q4 用"中位相接"贪心优先保**最短**，得 46 条/230 海里/漏测 7.69%/重叠>20% 128.68km；而优秀论文"分区+随梯度垂直变向+智能搜索"得 94 条/434.66km/**漏测 0.04%**/重叠>20% 仅 22km。
- **根因**：题目要求"条带**尽可能覆盖**全海域"为首要、且"重叠≤20%"，我只按"总长最短"选交付点，把覆盖牺牲到 92.3%，且深区重叠>20% 达 128km。
- **规避（铁律）**：真实地形布设是**多目标**：①先明确"覆盖最大"是首要约束（可设"漏测≤X%"硬约束）；②给完整 Pareto（总长-漏测率）供决策；③交付点别只取"最短端"，应取"**覆盖≥99% + 重叠≤20% + 总长较短**"的平衡点；④复杂地形优先"**分区 + 各带取与局部梯度垂直方向**"（"总最优≈局部最优之和"），而非统一方向贪心。
- **判断标准**：交付方案若漏测显著（>2%）或重叠>20% 段很长，即可能是"只求最短"的权衡点选偏；改"覆盖优先/Pareto 平衡点"。

## #23 流程达标 ≠ 内容竞争力达标：关键问用真优化、创新要结构级突破（高层次认知）

- **现象**：2023B 流程机制全达标（正文 29 页、三席盲评≥2 轮 84.2→87.3、三类图、判据严谨、国奖对比），但关键问 Q4 用"确定性贪心（取最短端）"而非真优化，漏测 7.69% vs 国奖 0.04%；B 席创新维度仅 74 封顶（"标准正确解法"）——仍卡在国一/国二边界。
- **根因**：把**流程质量**（页数/两轮审稿/三类图/判据/合规——可靠 persona 强制达成）与**内容竞争力**（关键问的优化深度、创新度——必须真本事）混为一谈。**流程达标 ≠ 好论文。**
- **后果**：流程全对但创新度偏中低、关键问用贪心近似 → 达不到国一。流程只能保"下限"，内容决定"上限"。
- **规避（铁律）**：①**最难的子问题必须用真优化**（多目标/整数规划/解析最优），不用贪心/弱启发式替代（贪心"取最短端"会牺牲覆盖漏测 7.69%）；②**创新要结构级突破**（如随曲线分段自适应变向、把首要目标纳入显式多目标、更普适的解析一致性论证），而非只做"标准正确解法"；③交付前自问"关键问是否真优化？创新点是否超出标准解法？"
- **判断标准**：审稿只挑流程层问题（排版/合规/数值）而关键问用了贪心/启发式、创新=标准解法 → 踩本坑。A/B 类多目标/布设/优化题反复出现。

## #24 审稿"确认修复落实"却放过硬伤：改措辞≠真修复、页数不足未回退（2024C 复盘）

- **现象**：2024C 三席盲评初评 A67.4/B67.3/C62.4（C 席"不获奖"），处理后复评"确认修复落实→趋于一致=国二"收工。但实际**正文仅约 12 页**（违背 20-32 页硬门禁）、双口径差~67% 只改图注声明、Pareto 自相矛盾改结论为"对θ不敏感"、逐步推导未补——全被"改措辞"掩盖，审稿没拦下任何硬伤，也没真正"改到质量好为止"。
- **根因**：审稿把"**改了字/改了图注**"当"**修复**"，把"**复评分数相近**"当"**达标**"，且把**页数这种一票否决的硬伤**放过——三段都缺硬校验。这正是 `#14`（跳过三席盲评）的变种：**三席做了，但没真正起到"改到好为止"的作用**。
- **后果**：审稿流于形式，论文带着硬伤（12页/未合口径/回避结论）以"国二"收尾，欺骗了流程、也骗了自己。**流程走全 ≠ 质量达标。**
- **规避（铁律，已入 persona 审稿硬校验）**：①**正文页数硬阻断**——≥20 页否则一票否决回退 Phase 3，禁止"12页确认通过"；②**真修复 vs 改措辞**——MAJOR 必须真解决问题（真合口径/真修正），不能只改图注/把结论改软兜过去；无法真修的明确标为已知局限并写入"模型评价-缺点"；③**复评分数必须上升**——复评 weighted 必须高于初评，单维破 floor 或未达目标档就继续复评（不限轮数），禁止"初评67复评国二就收工"。
- **判断标准**：审稿聚合出现"确认修复落实→implied_tier"但初评分数第1轮就很低（<75）、或复评分数与初评相近、或正文明显不足 20 页却通过 → 踩本坑。**强证据**：审稿给出的 MAJOR 多为"改表述/改图注/改软结论"而非"改模型/改数值/补推导"。

## #25 门禁越加越多，论文反而越做越薄：为"达标"而打勾，忘了推导厚度（2024C 高阶教训）

- **现象**：2024C 用了最"高级"的模型链（多期 MILP + 两阶段随机规划 + 均值--CVaR + 弹性/间作），正文却仅 **12 页**——比此前 2019A（33页）/2023B（29页）塌陷一半。三问全压缩进"4.1基础/4.2缺陷/4.3优化/4.4对比"模板，每问就两三段；问题三"结构级创新"只给了一个相关矩阵 + 一个弹性公式，**无任何逐步推导**；创新点对照表里"相关+弹性+间作"三行数字完全相同（20.37/0.59/19.40），"间作增益"实为空（审稿发现后删结论改列推广）。
- **根因**：**门禁设计过头，把 agent 的注意力引向"逐条打勾过关"而非"把论文做深做厚"**。`无懈可击审计`/`降重降AI味双检`/`创新雷达`等过程文档越完整，agent 越觉得"达标了"，反而不再花功夫于论文本体推导。**流程文档的"漂亮" ≠ 论文的"厚实"**——这是 `#23` 的极端版：从"关键问用贪心"升级为"**为达标而达标、忘了论文厚度才是真正目标**"。模型越复杂（MILP/随机规划），推导越薄（套模板），本末倒置。
- **后果**：流程记录全满分（三类图齐/4.4有/双检打过勾），但论文 12 页、推导空泛、创新虚 —— 撑不起含金量。**"可打勾"的检查项填得越满，越容易掩盖"论文本体没做透"。**
- **规避（铁律，先减法再加法）**：①**推导厚度是硬标准**——每问模型建立必须像 2019A 那样**从物理/经济/数理原理出发逐步推导**（守恒/目标→变量→约束→推导变形→最终式→数值），不允许"直接给最终模型/只给一个公式就带过"；页数是自然结果不是目标。②**砍掉"空转"的外观检查**——创新雷达/双检记录等过程文档，降级为"论文里真实体现"（写到推导/结果里），不单独产出漂亮表格糊弄检查；门禁少而硬 > 多而空。③**创新必须真成立**——给创新点要能真算出来（数值不重复、结论不空），不能"写了创新点名字"就算；结构级创新要落到"真改模型+真对比"。
- **判断标准**：论文模型最复杂、页数却骤降（比对同库其他题），推导多"套模板/一句话带过"，创新点对照有多行数值相同/空结论 → 踩本坑。**强信号**：agent 产出的过程文档（审计/检测/评分记录）比论文正文还多还完整。

## #26 "错了可以辩解"的题 + 无止损上报 → 调试螺旋、越改越坏（机理题实战教训）

- **现象**：某次机理题两次求解都陷入调试螺旋——调试脚本占全部文件 38%~40%；求解器**完全冻结**（关键状态量在所有网格/时间步下都不变），与解析解差 **59%~270%**；agent 拿到这些数字后继续写新调试脚本，**既不停止也不上报**。
- **技术根因（例证）**：求解器从未使用真实物理尺度——默认把计算域当成 1 m，实际是厘米量级，扩散时间尺度差数千倍；离散通量又少乘一个尺度因子。**这类"缩放型 bug"：算子恒等式查不出、网格收敛性也查不出（冻结的解在任何网格上都"收敛"），只有与解析解/物理量对照才能发现。**
- **行为根因（更致命）**：①**把检验失败合理化**——自检脚本已报出明显错误，报告却写"这是口径差别/不是误差/证明格式无网格依赖误差"，把一次失败的检验叙述成一次通过的检验；②**没有止损闸**——persona 只写"全自动：不询问、自决继续"，对"同一 bug 反复失败"没有任何停止条款，agent 就一路试下去。
- **为什么容易发生**：有解析解/守恒量/几何事实可对照的题，错了会被外部真值逼着改对；而移动边界 + 变物性非线性题**没有闭式解**，验证容易退化成"自己验证自己"，给了"合理化"的空间。**不是能力下降，是"验证锚"和"止损闸"两个缺失。**
- **规避（铁律，已入 persona「技术失败止损协议」）**：①**止损上报**——同一处 bug/验证失败 ≥3 次修复未过、或与基准偏差 >10% 修 3 次未收敛、或出现物理不可能结果（解冻结/质量不守恒/浓度不降反升/温度越过环境）→ **立即停下向用户报告**，禁止继续自试；②**禁止合理化**——检验不通过就是没通过，禁用"口径差别/等效形式/正常离散误差"话术，禁止改判据、放宽阈值、更换对比对象，**唯一合法的通过方式是把结果修对**；③**调试预算**——同一问题最多 3 个调试脚本，写第 4 个前必须停下查根因或上报；④**最小可验证原型**——先跑常物性+固定域+对照解析/守恒，通过后才允许上变物性/耦合/移动边界；⑤**无解析解必须双方法互证**（FVM vs CN vs scipy BDF）。
- **判断标准**：调试脚本占全部文件 >25%；同一处反复改格式/试参数；自检报告出现"这是口径差别/不是误差"等辩解性措辞；数值解对所有网格/时间步都不变（=冻结）→ 踩本坑。
