# aishumo 架构

## 1. 设计目标

aishumo 不是“一键生成论文”的提示词，而是把数学建模竞赛的交付过程拆成**可验证的阶段**：

- 每个阶段有明确产物和门禁；
- 代码必须真实运行，结果必须可追溯；
- 关键数值必须独立复算；
- 论文必须经过多视角审稿，而不是自审通过。

## 2. 阶段与产物

```
Phase 0 框架设计
  → Phase 1 逐题推导
  → Phase 2 逐题编码
  → Phase 2.5 独立验算
  → Phase 3 论文与编译
  → Phase 4 审稿（三席盲评，可回退）
```

| 阶段 | 产物 | 门禁 |
|---|---|---|
| Phase 0 | `求解/模型推导/框架设计.md` | 核心思想 / 核心量≤3 / 五问递进 / 命题树 / 题型判定 |
| Phase 1 | `求解/模型推导/问题X_数学推导.md` | 量纲、假设[强/弱]、方法理由 + 备选 |
| Phase 2 | `求解/问题X/问题X_求解.py`、`结果/*.csv`、`图片/*.png` | 实际运行，结果/图片非空 |
| Phase 2.5 | 独立验算报告 | 信息隔离复算；>30% FAIL、10–30% SUSPECT |
| Phase 3 | `论文/*.tex`、`main.pdf` | xelatex ×2，Error=0；摘要/页数/图表检查 |
| Phase 4 | 三席 `scorecard` + 聚合结论 | B1-B9 阻断项一票否决；三席盲评 ≥2 轮 |

## 3. 角色边界

| 角色 | 可以做什么 | 不可以做什么 |
|---|---|---|
| 主控 | 读题、分派、监控、回退、交付 | 跳过门禁、伪造产物 |
| 数学家 | 推导、假设、方法选择 | 改代码、改结果 |
| 工程师 | 编码、运行、产出结果与图 | 改推导口径、伪造数值 |
| 作家 | 写论文、编译、排版 | 改数值、改结论 |
| 审稿人 | 逐项检查、打分、阻断 | 与被审对象共享上下文 |

## 4. 关键机制

### 4.1 独立验算

Phase 2.5 另派 subagent，只读代码与结果，不读取推导文件；用不同方法复算关键数值。

- 分歧 >30%：FAIL，回退 Phase 2；
- 10–30%：SUSPECT，记录并说明；
- <10%：PASS。

### 4.2 三席盲评

Phase 4 派三个互不共享上下文的评委：

- A 旗舰通审：摘要、建模、结果、写作、完整性；
- B 创新与决策：创新点、证据、决策链；
- C 正确性可复现：正确性、可复现性、结果一致性。

每席只拿渲染后的 PDF 与产物清单，不告知目标档与阈值，避免评分锚定。

### 4.3 数字冻结

论文中的关键数字必须能追溯到 CSV 或脚本输出。代码修改后，重新检查论文引用，防止“改了代码忘改论文”。

### 4.4 技术失败止损

出现以下任一情况，停止自试并向用户报告：

- 同一 bug / 验证失败累计 ≥3 次修复仍未通过；
- 与基准解、解析解、守恒量偏差 >10%，修复 3 次未收敛；
- 出现物理不可能结果（解冻结、质量/能量不守恒、浓度不降反升、温度越过环境）；
- 安装/环境操作失败。

禁止把失败叙述成通过，禁止改判据、放宽阈值、更换对比对象。

## 5. 目录契约

- `SKILL_ROOT`：安装后的只读技能目录（`~/.dsh/skills/aishumo-method/`）。
- `PROJECT_ROOT`：用户的题目目录（可写），所有产物写这里。
- 输入附件只读；需要改模板时，先复制到 `PROJECT_ROOT`。

## 6. 扩展方式

- 新增模型：在 `知识库/模型工具箱/` 加一篇带 frontmatter 的文档，并在 `知识库/模型工具箱/算法工具箱_竞赛用法速查.md` 登记。
- 新增失败模式：追加到 `知识库/失败模式库.md`。
- 修改角色：编辑 `aishumo/presets/aishumo/agent.cordis.yml` 的 persona 文本。
- 修改论文模板：编辑 `知识库/模板/国赛LaTeX/`。
